# LocalP2PChat

局域网 P2P 聊天工具(无需服务器,直连/组网通信,支持加密传输、文件与音视频通话)。

## 目录结构

```
├── android/   # Android 版（Kotlin + Compose）
└── windows/   # Windows 版（PyQt6，已实现）
```

## Android 版

- Android 客户端源码位于 `android/`,基于 Gradle + Kotlin 构建。
- 群组管理(群主权能):群主可修改群名称与群公告(新包 `group_update{groupId, groupName?, announcement?}`),成员端落库持久化并在群大厅顶部显示公告横幅;群主可将成员移出群组(新包 `kick_member{groupId, targetId}`,定向投递给被移出者并在群内广播),被移出者立即清理该群全部连接、从群列表移除(本地聊天记录保留)并收到提示,其他成员把该成员从成员列表移除。两条传播路径(群主中继 + 成员间 mesh)都会处理,且只有群主(`senderId` == 群信息中的 `creatorId`)能发起,非群主发起的管理包一律忽略并断开。群主改名不影响数字入群 ID(创建时冻结并持久化),成员重进群、重连后群名/公告仍然生效。
- 功能:局域网成员发现、直接聊天、群组网状聊天(主机离线也可用)、离线历史、文件传输、视频/语音通话、多人语音会议。成员列表与直聊页均可发起视频或语音通话;`call_offer.media` 为 `"audio"` 时双方都不采集视频,纯语音通话界面(头像占位、静音/挂断)。每次通话结束都会在本地写入一条通话记录(去电/来电、接通/未接/被拒/取消/未接通、时长、是否视频),并在对应直聊会话中以系统样式行穿插显示(如「未接来电 14:32」),点击可直接回拨;未接来电在 Android 端还会发一条可点击跳转到该会话的通知。通话记录为纯本地数据(每会话保留最近 200 条),不进入聊天协议、不做端到端同步。**群组语音会议**(音频、星型拓扑):发起者成为会议主机并混音(混音减自己,自己不会听到自己),向群内在线成员定向发送 `group_call_invite`;被邀请成员响铃(45 秒超时),接受后发送 `group_call_join` 并拨通主机媒体端口;媒体链路与 1:1 通话完全相同(身份签名握手 + `call_media_hello` 校验 + AES-256-GCM 帧,`CallInfo.meetingId` 绑定会议);`group_call_sync` 在成员进出时向全员同步参会名单;会议与 1:1 通话互斥(共用麦克风)。聊天(群组+直连)、通话信令与媒体均全程 ECDH 握手加密;例外是文件字节流,采用 per-file 随机对称密钥的 AES-256-GCM 加密,该密钥本身经 ECDH 加密消息通道分发(下载握手行为 `file_download` 请求行含 uuid fileId 与可选下载 token=Base64(HMAC-SHA256(fileKey, "lc-file-dl-v1:"+fileId)),发送方恒时校验:token 存在但错误即拒绝,缺省(旧对端)才放行)。聊天与通话线路在同一连接内记录已见 nonce,发现重放即断开;加密包内附加逐方向严格递增的 `seq`(接收端要求恰好加一,拒绝重放/乱序/注入),对旧版本(不携带 `seq` 的)对端仍兼容:其报文持续放行,直到对端首次携带 `seq` 后才强制校验。消息删除采用墓碑收敛:在线成员即时删除,离线成员重连后经 `join_ack`/`history_reply` 的 `deletedIds` 补齐(每群上限 200 条,单包上限同值)。注意:无密码群组的加密仅防被动嗅探、不防主动中间人,建议创建群组时设置密码;首次添加联系人时建议在两端核对安全码(指纹),防止首次接触被中间人;删除消息的授权以"持有群组口令的成员"为界(墓碑不携带作者校验),口令泄露即等于成员可让全群删除任意消息。
- **二维码邀请**:两端互通的联系人/群邀请二维码(`localchat://contact?…` / `localchat://group?…`,URL 编码 UTF-8)。「我的二维码」携带本机名、安全码与局域网地址,对方扫码即可添加联系人;扫码得到的安全码会**预先钉住**该地址的身份指纹——首次握手必须出示完全一致的密钥,扫码到拨号之间被中间人替换会直接拒绝(不只是肉眼比对)。群邀请二维码只含 8 位数字 ID、入群端点(任一成员均可作为入口)与可选中继地址,**绝不含群密码**——入群仍需手动输入密码;扫码后自动填入加入表单。Android 端用相机扫码(ZXing core),Windows 端支持从图片识别或粘贴二维码文本;两端编码解码字节一致,可跨平台互扫。
- 双模拟器 / 真机端到端调试脚本见 `android/tools/emulator_e2e.py`。

## Windows 版

- 完整 Windows 桌面版位于 `windows/`，基于 PyQt6，功能与 Android 端互通。
- 群组管理与 Android 端同协议:`group_update`(群主改名/公告)、`kick_member`(群主移出成员);群大厅显示公告横幅,群主有「群设置」入口与成员行「移出」按钮。
- 通话同样支持视频/语音两种类型与本地通话记录：群成员列表与直聊页均有「通话」「语音」入口；会话内的通话记录系统行可点击回拨（语音记录回拨语音、视频记录回拨视频）。存储表见 `windows/localchat/storage.py` 的 `call_logs`。群大厅有「语音会议」入口（发起多人语音会议，见上文协议说明）。
- **群消息设备签名（TOFU）**：群消息/删除/编辑与群主管理包（`group_update`/`kick_member`）可选携带作者长期身份密钥签名（`senderPubId`/`senderSig`，transcript 域 `lc-group-v1`，长度前缀防拼接）。某成员首个有效签名会与本机绑定（TOFU 记录持久化），此后该成员的**未签名**包按重放类拒绝、**换密钥**一律拒绝；老对端未签名时照常放行，直到其开始签名。成员列表对已绑定成员显示「已验证」徽标与「安全码」按钮，可与对方设置页当面比对。
- **二维码**：设置页「二维码」出示本机联系人二维码；成员页「添加成员」可扫对方二维码（图片识别或粘贴文本）；群大厅/群设置可出示「群邀请二维码」；「加入群组」页可扫码自动填入数字 ID 与地址。桌面端依赖可选 `qrcode`（生成）与 opencv（识别），未安装时自动降级（展示二维码文本 + 复制按钮）。

## 本地功能（消息搜索 / 表情面板 / 通知快捷回复）

以下功能为纯本地实现，不涉及网络协议改动，两端各自独立、无需版本一致即可使用：

- **消息搜索**：Windows 在成员页工具栏「搜索」入口进入搜索结果页，可选范围（全部会话 / 某个群聊 / 某位成员）并按关键词搜索；Android 在会话页顶部搜索图标内搜索本会话，成员页顶部搜索图标进入全局搜索页（可选范围）。结果列表显示「会话名 + 发送者 + 摘要 + 时间」，点击后跳转到对应会话并滚动定位、短暂高亮该消息。搜索覆盖群聊与直聊的历史记录，媒体/文件消息按文件名匹配，正文匹配文本内容。实现说明：消息正文在本地数据库中是加密存储的（`enc1:` 前缀），因此存储层对静态明文列（发送者、文件路径、文件夹名）用转义的 SQL `LIKE` 预筛选（转义 `%`/`_`/`\`），正文则解密后逐条匹配。
- **表情面板**：两端输入区都有表情按钮，弹出按「最近 / 贴纸 / 笑脸 / 手势 / 动物 / 食物 / 物品 / 符号」分组的 Unicode emoji 面板，点击后在输入框光标处插入；最近使用的 24 个表情保存在本地并跨重启保留。「贴纸」页是一组精选大表情，发送后两端都以大号贴纸样式渲染（纯文本消息，无图片资源、无协议改动，旧版本对端只会看到一条短 emoji 消息）。
- **Android 通知快捷回复**：消息通知带有「回复」快捷输入（RemoteInput），可直接在通知栏输入并发送——群消息回到对应群、私聊消息发给对端；发送后自动清除该会话的未读与通知。回复走原有发送路径（ViewModel 的群组中继 / 直聊会话），离线私聊会像界面发送一样暂存待发；应用未在运行时群组回复无法送达，会以提示告知。后台直聊消息现在也会发出通知（与群聊共用同一通知合并逻辑与快捷回复）。
- **语音消息**：输入区麦克风按钮点击开始录音（最长 60 秒，按钮显示秒数），再次点击发送。两端统一录制 16 kHz 单声道 16-bit PCM WAV（普通文件通道发送，无编解码依赖）；气泡显示「▶ + 时长」，点击本端播放（Windows 需 `sounddevice`，Android 用 MediaPlayer），未下载时点击先接收再播放，长按提供回应/置顶/删除。未安装 `sounddevice` 时 Windows 隐藏录音按钮、语音气泡退化为系统播放器打开。Windows GIF 图片在会话内按帧动画播放（Android 显示首帧）。

## 消息体验（消息编辑 / 表情回应 / @提及 / 置顶 / 群已读回执）

以下功能走聊天协议扩展，**两端需同为包含该功能的版本才能完整生效**；所有新增字段均为可选字段，旧版本对端忽略未知字段，聊天/文件/通话不受影响：

- **消息编辑**：长按/右键自己的文本消息「编辑」，两端即时更新并显示「已编辑」角标。授权与删除一致：改写请求必须声明为原消息作者，且不得通过别的成员代传；与删除墓碑处于**同一信任边界**（网状链路的对端身份是握手自报、未做设备身份签名绑定，历史推送里的改写也只接受「作者经其自称链路推送自己的消息」），因此防伪以「持有群组口令的成员」为界——口令泄露即等于成员可改写/删除任意消息，与删除的既有说明一致。群组在线成员经 `edit_message` 包即时收敛；离线成员重连后经网状历史推送收敛（`edit_message` 与历史推送两条路径都按同一作者规则校验）。直聊为实时语义（与删除一致）：对方不在线时编辑不可发送。
- **表情回应**：消息菜单「回应」提供 6 个快捷 emoji（👍❤️😂😮😢🎉），气泡下方以药丸聚合计数，再点取消；`reaction` 包带 `active` 开关语义。回应为在线语义（不排队补发，与正在输入一致），本地持久化、重启保留。
- **@提及**：群聊输入「@」弹出成员选择（含 @所有人），发送的 `ChatMessage` 携带可选 `mentions` 字段（成员 id 列表，`all` 表示所有人）；被提及者的气泡金色描边高亮。
- **置顶消息**：消息菜单「置顶/取消置顶」，任何成员可置顶；会话顶部横幅显示最新一条置顶（点击跳转、✕ 取消），本地持久化。`pin_message` 包带 `active` 开关语义，在线同步。
- **群聊已读回执**：打开群聊并读到最新消息时发送群范围的 `read_receipt`（复用直聊回执包，groupId 为群 id）；成员收到后只标记自己的消息，自己的群消息显示「已读 n/m」（n=已读成员数，m=其他成员数），判定阈值与直聊一致（时间戳 ≤ 回执消息）。

## 文件断点续传与进度详情

- 下载握手 `file_download` 请求行现在**必带 `offset` 字段**（已收字节数，非负整数）：0 表示全新下载，大于 0 表示从中断处续传；`offset` 超过发送方声明的大小时直接拒绝（不返回 meta、不发送任何字节）。发送方从该偏移 seek 后流式发送；`offset == 文件大小` 时只回 meta 与 EOF 标记，接收端据此完成落盘。
- 接收端把解密分片追加写入临时文件（Windows/桌面为 `<目标>.part`；Android 因 SAF 文档没有同目录临时文件，统一写入应用私有 `downloads/<fileId>_<文件名>.part` 暂存文件），完成后才原子落盘：桌面端 `os.replace`，Android 媒体文件 `renameTo`、用户选择的 SAF 文档则复制后删除暂存文件。
- 下载中断（连接断开/取消/应用退出）**保留暂存文件与已收字节数**：状态持久化在本地（Windows 存于加密的设置项 `file_download_resume_v1`，Android 存于 Keystore 包裹的 prefs `file_resume_<fileId>`，其中包含续传所需的下载地址与 per-file 密钥），应用重启后文件卡片仍显示「已暂停 xx%（点击续传）」，再次点击自动从断点继续；文件夹传输逐文件适用（已完成条目会跳过）。
- 取消语义两端一致：**取消 = 保留断点**（显示「已暂停」，再次点击续传），不删除暂存文件。
- 下载中的卡片实时显示「下载中 N%」与进度详情「已传/总大小 · 速度 · 剩余时间」；刷新节流保证至少 4 次/秒（250ms 或 256KB 或 5% 阈值，任一触发）。
- 加密线层不变：每个分片仍是独立的 AES-256-GCM 报文，格式为 `nonce(12B) || ciphertext || tag(16B)` 外加 4 字节大端长度前缀，**nonce 每片随机生成**，与偏移无关，因此续传不改变任何 GCM 参数（两端一致）。校验失败（token 错误、GCM 标签不符、大小不符等）与安全底线保持不变，不因兼容放宽。

## 版本兼容说明

- 通话功能要求 **两端（Android 与 Windows）均为最新版本**：媒体通道建立时需完成 `call_media_hello` 校验，旧版本客户端无法与本版本通话（表现为"对方未接听/媒体通道校验失败"）。文件断点续传同理：`file_download` 的 `offset` 为必需字段，新旧版本混用时文件下载会失败（项目尚未发布，未保留旧版兜底）；请两端同步升级。聊天与群组功能不受影响。
- 群组管理（改名、公告、移出成员）要求 **两端均为包含该功能的版本**：旧版本对端不认识这两个包会直接忽略（聊天、文件、入群不受影响，只是管理动作不生效）。升级后如群管理不生效，请确认对方也已升级。
- `call_offer` 新增可选字段 `media`（`"audio"`/省略=`"video"`）。旧版本对端会忽略该字段并按视频处理，而视频帧仍受 `call_media_hello` 版本校验约束，因此新旧混合仍无法通话（与上述规则一致）。通话记录为本地数据，任何版本组合都不影响其写入与显示。
- **消息体验功能（编辑/回应/提及/置顶/群已读）**：新增包 `edit_message`/`reaction`/`pin_message` 与 `ChatMessage` 可选字段 `mentions`/`edited`、文件消息新类别 `audio` 均为可选字段，旧版本对端忽略未知字段、`audio` 退化为普通文件卡片（可下载、可外部播放），聊天/文件/通话不受影响。与旧对端混用时这些动作不生效或仅本端可见（编辑/置顶/回应/已读不跨版本同步）；两端都升级后立即恢复完整体验。
- **群组语音会议**：两端需**均为包含该功能的版本**才能参会——旧版本对端不认识 `group_call_*` 包会直接忽略（表现为收不到会议邀请，聊天/文件/1:1 通话不受影响）。媒体链路复用 1:1 通话的身份握手 + `call_media_hello` 校验，`CallInfo.meetingId` 为可选字段（旧对端省略），1:1 通话报文字节不变。
- **群消息设备签名（TOFU）**：`senderPubId`/`senderSig` 为可选字段，老版本对端忽略未知字段；新版本对老对端的**未签名**流量始终放行，直到对端首次携带签名后才强制校验（`seq` 同款升级策略）。因此新旧混用不破坏聊天/文件/群管理；只有两端都升级，成员徽标与签名防伪才完整生效。
- **二维码邀请**：载荷为纯文本 URL，新旧版本之间不存在兼容问题（不涉及既有协议面）；扫码添加联系人时安全码预钉依赖两端的 TOFU 校验，旧版本对端无此校验时仅跳过钉定、不影响连接。

## 构建

### Windows 版

```bat
cd windows
pip install -r requirements.txt
python main.py
```

### Android 版

用 Android Studio 打开 `android/` 目录构建安装，或：

```bat
cd android
gradlew assembleDebug
```
